Scheduled actions

Staged fleet updates

Apply apt updates fleet-wide in waves: a canary group first, then the remainder, with a health gate (critical-service check, and a reboot + re-verify if the update left one pending) after every wave. A failed gate halts the rollout and notifies — later waves never run. Each device only updates while it is inside its own configured maintenance window. Select devices by role and/or tag; apt.upgrade must be in that device's allowed_actions.

Alert correlation

Groups open alerts that share a trigger class and network context (same Wi-Fi SSID, gateway, or IP subnet) within a rolling window into one explainable cluster card on Alerts, and batches their notifications. Grouping only — no alert is ever merged or suppressed. Enabled by default; override with the alert_correlation section in config.json (restart required).

Anomaly detection

Statistical baselines (EWMA with hour-of-day seasonality) flag unusual-but-not-threshold values — slow memory growth, off-pattern traffic spikes, and the like. Disabled by default; add the anomaly_detection section to config.json (restart required). In preview mode (the default) deviations are recorded below without opening alerts, so you can judge the noise level before enabling real anomaly alerts.
